## Task 1: P2-1 后端 — fund-screen 新增 codes 参数

**目标**：解决心愿单请求 `top_n=2000` 的浪费，改为按代码列表精确查询

**Files:**
- Modify: `backend/api/signals.py` — `/api/fund-screen` 路由增加 `codes` 参数
- Modify: `backend/services/fund_screen.py` — `screen_funds()` 支持 codes 过滤
- Modify: `backend/services/tushare_data.py` — 批量查少量基金净值时走快路径

**Step 1: 修改 signals.py 路由，增加 `codes` 查询参数**

在 `@app.get("/api/fund-screen")` 的函数签名中增加可选参数：

```python
@app.get("/api/fund-screen")
async def get_fund_screen(
    fund_type: str = "all",
    sort_by: str = "score",
    top_n: int = 30,
    userId: str = "",
    codes: str = "",  # 新增：逗号分隔的基金代码列表
):
```

当 `codes` 非空时：
- 解析为 `code_list = [c.strip() for c in codes.split(",") if c.strip()]`
- 将 `code_list` 传入 `screen_funds(codes=code_list, ...)`
- 忽略 `fund_type`/`sort_by`/`top_n`（按 codes 精确查询不需要排序筛选）

**Step 2: 修改 fund_screen.py screen_funds() 增加 codes 快速路径**

```python
def screen_funds(fund_type="all", sort_by="score", top_n=30, user_id="", codes=None):
    """
    codes: 可选，指定基金代码列表时跳过全量筛选，只查这些基金的详情
    """
    if codes:
        # 快速路径：只查询指定的几只 ~20 只
        return _screen_specific_codes(codes, user_id)

    # 原有逻辑不变...
```

新增 `_screen_specific_codes()` 函数：
- 接收 code 列表（如 `["110022","000001"]`）
- 对每只代码调用 Tushare `fund_basic` + `daily_basic` 获取基础数据+估值
- 如果有 userId，调用 `_compute_fund_screen()` 做个人化富化
- 返回格式与原 `screen_funds()` 完全一致（funds 列表）

## Task 3: P1-2 后端 — detail 接口增强持仓数据

**目标**：让非持仓详情接口也能选择性返回持仓增强数据（合并 2 个接口为 1 个调用场景）

**Files:**
- Modify: `backend/api/fund_detail.py:391` — `get_fund_detail()` 增加 `userId` 参数

**Step 1: 修改 /api/fund/detail/{code} 路由**

```python
@router.get("/api/fund/detail/{code}")
async def get_fund_detail(code: str, userId: str = ""):
    """基金详情（含可选持仓增强）"""
    result = _build_fund_detail(code)

    # 如果传了 userId 且用户持有该基金，补充持仓决策数据
    if userId:
        holding_data = _enrich_holding_detail(code, userId)
        if holding_data:
            result.update(holding_data)

    return result
```

**Step 2: 新增 _enrich_holding_detail() 辅助函数**

从 `get_fund_holding_detail()` 中提取公共逻辑：
- 检查 userId 是否持有该基金（读用户 JSON）
- 如持有 → 计算 advices/dca/pnl/nav_percentile 等
- 返回 dict 或 None（未持有时返回 None，不污染基础详情）

**注意**：不要复制粘贴 `get_fund_holding_detail()` 的全部代码，而是抽取共享函数。
