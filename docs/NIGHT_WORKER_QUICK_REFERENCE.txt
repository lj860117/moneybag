🎯 HOW TO ADJUST FUTURES TIMING
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Option A: Separate cron for futures-only
  ─────────────────────────────────────────
  30 7 * * * cd /opt/moneybag/backend && \
    python scripts/night_worker.py --step overnight >> /opt/moneybag/logs/futures.log 2>&1

  Option B: Add 30-min cache to futures function
  ───────────────────────────────────────────────
  In indicators.py (line 580):
    _futures_cache = MemoryCache(default_ttl=1800)  # 30 min
    # Then check cache before calling AKShare

  Option C: Run earlier for Asia pre-market data
  ───────────────────────────────────────────────
  0 22 * * * python scripts/night_worker.py --step overnight  # 22:00 UTC = 06:00 Shanghai

  Option D: Run later but separately
  ────────────────────────────────────
  0 8 * * * python scripts/night_worker.py --step overnight   # Just before push (08:00 UTC)

⚠️ KEY ISSUES & RECOMMENDATIONS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. ❌ fund_rank_build.py not in crontab
     → Recommendation: Add daily schedule post-market
     → Currently manual trigger only!

  2. ❌ Futures data has NO caching
     → Every call hits AKShare API
     → Recommendation: Add 30-min TTL in-memory cache

  3. ❌ No trading session validation for futures
     → No check if data is fresh/correct session
     → Recommendation: Validate timestamp in AKShare response

  4. ✅ Precomputed cache working correctly
     → 2-4 hour TTLs per data type
     → Auto-extends on weekends

  5. ✅ night_worker cron configured correctly
     → 01:00 UTC daily main run
     → 08:30 UTC weekdays backup push
