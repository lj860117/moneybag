| 总成本 | 709 元 |
| `addedAt` 时间戳 | **8 条记录完全相同**（同一次批量录入，无逐笔定投痕迹） |

「7×100 元 + 1×10 元、`addedAt` 全同」是**批量造测试数据的典型特征**，不是真实定投账户的形态 —— 真实账户的成本会是随定投日期分散的不规则数字，`addedAt` 也必然各不相同。用户（LeiJiang）已明确表态**会重录真实持仓**。

### 0.0.2 后果：本 PRD 里所有「占你总净值 X%」的数字，现在都不可信

根因在公式本身。穿透暴露的计算是（见 §6.2、设计文档 §3.4）：

```
exposure[个股] = Σ_fund ( weight_mv[fund] × stk_mkv_ratio[fund][个股] / 100 )
                              ↑
                        ← 直接来自持仓市值权重
```

**`weight_mv` 是持仓数据的函数。** 等权测试数据把 8 只基金的权重人为压成了近似相等的 1/8（真实数据里某只基金完全可能占 40% 而不是 12.5%）。而且这个偏差**不是等比缩放**：权重一变，集中度会向重仓基金所属行业整体倾斜，行业排名可能重排，个股暴露可能翻倍或腰斩，**变化方向无法预测**。

| 类别 | 包含哪些数字 | 重录真实持仓后 |
|---|---|---|
| **A. 权重类 —— 全部作废** | 穿透覆盖率（61.79% / 线上 63.0%）、QDII 盲区占比（24.43% 市值 / 28.09% 成本 / 线上 25.1%）、残差（13.78% / 线上 12.0%）；行业集中度（半导体 33.47% / 线上 33.92%、电子+通信 55.5%、通信设备 13.31%）；个股重复押注暴露（北方华创 4.53% / 线上 4.48%、芯源微 3.98%、新易盛 3.95%）；§1 持仓表的「市值占比 / 成本占比」**整两列**；P1-2 归因的全部暴露值；P1-3 的 46.78% 敞口；**组合整体相对成本 -2.21% / 线上 -3.99%（均为口径 A：成本加权 = 总市值/总成本−1，见 §0.0.5）** | 🔴 **作废，必须重算** |

### 0.0.3 为什么现在不直接换成真实数据

因为真实持仓还没录。等权测试值是当时唯一能让 C 方案端到端跑通、验证链路与文案形态的数据。**它的作用是「证明系统算得出来」，不是「告诉你结论是什么」。** 这两件事必须分开看 —— 上线跑出来的 63.0% 覆盖率和 33.92% 半导体，验证的是代码正确性，不是用户的风险画像。

### 0.0.4 重录真实持仓后必须重新校验的清单（6 项）

1. **重跑穿透三分解**：`penetrated + blind + residual == 100%`。三个数**都会变** —— 若 QDII 被重仓，盲区可能从 25% 跳到 40%+，届时「覆盖率 63%」的说法要整体改写。
2. **重算行业集中度与重复押注 Top3**。判定门槛是固定阈值（行业 >25% / 个股 >3% / ≥3 只基金共持），但**结论可能从「触发」翻转为「不触发」**，反之亦然 —— 这会直接改变 P0-1 的推送频率。
3. **重算组合整体相对成本**（-2.21% / 线上 -3.99%，均为**口径 A**）。单只基金的 -26.95% 不变，组合口径必然变。
   ⚠️ **重算时必须用口径 A（`总市值 / 总成本 − 1`），不得用口径 B（市值加权平均收益率）** —— B ≥ A 恒成立，会系统性高估收益。两个口径的定义、恒等式与实测对照见 §0.0.5。
4. **重估 §5.1 推送预算**：P0-1 频率依赖集中度是否过门槛，预算表要跟着重算。
5. **复核 §0「最有价值的单一发现」整段** —— 33.47% 半导体集中度、4 只基金买同一只票。这是本 PRD 价值最高的结论，也**最依赖权重**。真实持仓下它可能更强，也可能根本不成立。**在重录之前，这条结论只能当作「系统能算出这个形态」的演示，不能当作对用户的事实陈述。**
6. **复核 §9.2-4 QDII 盲区（24.43% / 28.09%）的产品化表达**：占比变了，前端标记与文案里的数字要同步，否则会又一次出现「文案里的数字和真实敞口对不上」。

### 0.0.5 组合整体相对成本的两个口径（2026-09-05 澄清：**不是缺陷，无需排查**）

> **本节取代了本 PRD 前一版的「未解释差异」。** 原表把「组合整体 -2.21% vs -3.99% 差 1.78pct」列为「调研脚本与线上实现可能不一致、重录前应查清」。**该判断已证伪：线上实现是对的，调研脚本也没有错，两者都是口径 A，差异全部来自净值日期漂移。**

#### 两个口径的定义

| 口径 | 公式 | 别名 | 2026-09-04 调研值<br>（净值日 09-03 / QDII 09-02） | 2026-09-05 复测值<br>（净值日 09-04 / QDII 09-03） |
|---|---|---|---|---|
| **A（权威）** | `Σ市值 / Σ成本 − 1` | **成本加权平均收益率**<br>`Σ cost_weight_i × r_i` | **−2.21%** | **−3.99%** |
| **B（禁用）** | `Σ(weight_mv_i × r_i)` | **市值加权平均收益率** | −0.02% | −2.05% |

#### A 与 B 的差可精确预测，不是误差

```
B − A = Var_c(r) / (1 + A)
```
其中 `Var_c(r)` = 各基金收益率按**成本**权重的加权方差。

**2026-09-05 服务器实测校验**：`B − A = +1.9450 pct`，恒等式预测 `+1.9450 pct`，**残差 ≈ 0.0000 pct**（残差仅来自 `portfolio.py:149` 把 `weight_mv` 取整到 2 位小数）。两个口径数学上必然不等，差多少能算出来，**不是算法不一致**。

#### 三条规则

1. **口径 A 是唯一可用于给用户看的收益率** —— `总市值/总成本 − 1` 就是用户真实的盈亏，也是全代码库的既有口径（`portfolio_overview.py:112-115`、`cfo_dashboard.py:224-225`、`api/portfolio.py:242-253`、`scripts/night_worker.py:947`、`fund_signal/dca.py:65` 全部是 A）。
2. **口径 B 系统性高估收益，B ≥ A 恒成立** —— 因为 `weight_mv_i ∝ cost_i ×(1+r_i)`，涨得多的基金自动拿到更大权重。**B 是基金评价口径，禁止用于给用户看收益率。**
3. `weight_mv` 在 `backend/` 中只用于 xray 穿透二次加权、render 展示文案、快照字段带出，**没有任何地方用它加权收益率**。口径是全局一致的。

#### 那 1.78pct 到底是什么 —— 净值日期漂移，已逐只核实

**−2.21% 与 −3.99% 同为口径 A**，不是分属两个口径。2026-09-05 服务器全精度复测（逐只对比）：

| code | PRD 表（净值日 09-03 / QDII 09-02） | 09-05 复测（净值日 09-04 / QDII 09-03） | 变动 |
|---|---|---|---|
| 013107 | +18.81% | +16.67% | −2.14 pct |
| 002163 | +11.13% | +7.08% | −4.05 pct |
| 016501 | +7.89% | +4.19% | −3.70 pct |
| 005851 | −9.26% | −11.20% | −1.94 pct |
| 008984 | −13.36% | −15.23% | −1.87 pct |
| 007356 | −11.41% | −13.21% | −1.80 pct |
| 006555（QDII） | −2.80% | −1.81% | +0.99 pct |
| 005698（QDII） | −26.95% | −26.72% | +0.23 pct |
| **组合（口径 A）** | **−2.21%** | **−3.99%** | **−1.78 pct** |

**6 只境内基金在一个交易日内普跌 1.8~4.1 pct；2 只 QDII 因净值滞后（T+1 / T+2），净值日只推进了一天且方向相反、微涨。** PRD 表的净值日比复测早一个交易日 —— 这就是 1.78pct 的**全部来源**，无其他因素。

> ⚠️ **一个易犯的对照错误（本项目已犯过一次，记录在案）**：把「−2.21%（口径 A，09-04）」与「−2.05%（口径 B，09-05）」放在一起比，会得到「只差 0.16pct，是日期漂移」的错误结论。这两个数是**不同口径 + 不同日期**，0.16pct 是巧合。**同口径对比只能 A 对 A（−2.21% → −3.99%）或 B 对 B（−0.02% → −2.05%）。**

## 0. 结论先行

> **这个通道不该关，但必须换掉全部内容。**

用户账户里 **8 只基金、0 只股票**。当前 `collect()` 的 5 个采集器（news / holder_change / unlock / fund_flow / technical）里，**3 个是个股事件类**（holder_change / unlock / fund_flow），对纯基金账户结构性地产出 0 条有效信号 —— 这不是阈值问题，是标的类型不匹配。修 bug 只能让它从「推错的」变成「什么都不推」。

实测三个关键判定：

1. **解禁穿透不可行**（不是「数据拿不到」，是「拿到了也没有」）。分页取全未来 90 天 `share_float` 共 **102,000 行 / 190 只标的**，与用户穿透后的 35 只 A 股重仓股取交集，只命中 **1 只**（300395.SZ，2026-12-01，占总股本 **0.66%**）—— 连现有代码 `warning` 门槛（>2%）都达不到。
2. **增减持信号目前产出的是错误数据**（详见 §8 存量 Bug B3）。`stk_holdertrade` 根本没有 `change_type` / `change_amount` 字段，现有封装请求了这两个不存在的字段 → 方向恒判为「减持」、金额恒显示「0万元」、股数放大 10,000 倍。这与代码里已修复的北向 `net_amount` 幽灵字段是同一类 bug，只是还没被发现。
3. **真正有价值的信号存在，但形态和现在完全不同**：不是「某只股票发生了什么」，而是「你这 8 只基金作为一个组合，出现了什么结构性变化」。

**最有价值的单一发现**（用户自己不可能知道，且直接可操作）：

用户以为买 8 只基金是分散，穿透后 6 只国内基金的前十大重仓**高度重合**：

- 半导体一个申万二级行业 = **33.47% 总净值**；电子+通信申万一级合计 **55.5%**
- 北方华创(002371) 被 **4 只**持仓基金同时重仓，穿透暴露 4.53%
- 新易盛(300502)、源杰科技(688498) 各被 **4 只**基金重仓
- 穿透到的 39 只个股中，半导体 12 只 + 通信设备 5 只 + 元器件 2 只 = **95% 挤在同一条产业链**

这一条信息的价值，高于过去所有推送的总和。

> 🧪 **但上面这一整段现在不可信，请勿直接引用。** 33.47% / 55.5% / 4.53% / 95% 全部由持仓市值权重推导（公式见 §0.0.2），而生产持仓是**等权测试值**（7×100 元 + 1×10 元，8 条 `addedAt` 完全相同），用户将重录真实持仓。重录后这些数字可能更强，也可能根本不成立。**在重录前，它只能当作「系统能算出这个形态」的演示，不能当作对 LeiJiang 真实风险画像的事实陈述。** 详见 §0.0。

**当前账户状态（实测，写进 PRD 是因为它决定了优先级）**：8 只基金相对 60 日高点全部处于 **-24.29% ~ -39.32%** 回撤；但**相对用户成本净值，组合整体只有 🧪-2.21%**（线上实测 🧪-3.99%），其中 **3 只浮盈**（+7.89% ~ +18.81%）、5 只浮亏，最深的 005698 为 **-26.95%**（线上 -26.72%）。

> 上句中：单只基金的 **-26.95% 与 +7.89%~+18.81% 不受影响**（百分比类，只依赖 `unit_nav / cost_nav`）；**组合整体的 -2.21% 作废** —— 它是「总市值/总成本−1」（**口径 A**），分子分母都由持仓份额决定，等权测试值一改就变。
>
> ⚠️ 注意区分：这里说的「受权重影响」**不等于**「它是市值加权」。口径 A 是**成本加权**平均收益率；市值加权（口径 B）给的是 -0.02%，**禁止用于给用户看的收益率**。两者定义见 §0.0.5。
>
> 仅「当前账户状态」这一句里就同时存在两类数字，是全 PRD 最容易被误读的地方。

> **这组数字是 v2 最重要的修正。** v1 用「滚动 60 日高点」基准，得出「8 只基金全部深套 -24%~-39%」；换成成本基准后，真实画面是：**用户在低位买入后曾大幅上涨，现在只是从高点回落，相对自己的成本基本打平。** 同一个账户、同一天的数据，两个口径给出完全相反的情绪结论 —— 这正是用户选择成本基准的原因，也是 §6.2 单位口径表必须强制执行的理由。

> 🧪 **第 3 条的组合数值作废，第 4 条的算法规则不变。** 组合整体 = `总市值 / 总成本 - 1`（**口径 A / 成本加权**），分子分母都由持仓份额决定，等权测试值一改就变；而「必须用 `总市值/总成本-1`（口径 A）而非市值加权平均（口径 B）」这条**算法规则本身与权重无关**，继续有效。
>
> **两个口径的对照数值（含 2026-09-05 复测）**：
>
> | 口径 | 公式 | 09-04 调研 | 09-05 复测 | 用途 |
> |---|---|---|---|---|
> | **A（成本加权）** | `总市值/总成本 − 1` | **−2.21%** | **−3.99%** | ✅ **唯一可用于给用户看的收益率** |
> | **B（市值加权）** | `Σ(weight_mv_i × r_i)` | −0.02% | −2.05% | ❌ 基金评价口径，**禁用** |
>
> **B ≥ A 恒成立**，差值由恒等式 `B − A = Var_c(r)/(1+A)` 精确决定（实测残差 ≈ 0）。原因：`weight_mv_i ∝ cost_i ×(1+r_i)`，涨得多的基金自动拿到更大权重，于是 B 系统性高估收益。详见 §0.0.5。
>
> 上表两组对照都是等权测试值下的示例，真实持仓下具体数值会变，**但 B ≥ A 的方向与恒等式永远成立**。

## 2. 产品目标（3 个，正交）

1. **G1 — 换掉标的类型**：信号从「个股事件」切换到「基金/组合事件」，让纯基金账户的有效信号数从 0 变成非 0。
2. **G2 — 组合视角替代逐条视角**：推送回答「我的组合发生了什么结构性变化」，而不是罗列「市场上有哪些事」；每条推送都要能让用户指向自己的某只基金。
3. **G3 — 诚实标注数据边界**：每条信号必须自带「数据时点 / 滞后天数 / 覆盖率」；覆盖不到的部分（🧪 QDII 24.43%，线上实测 🧪25.1%）显式声明，绝不让用户以为看到的是全貌。

> 🧪 G3 里的 24.43% 会随真实持仓变化，但 **G3 这条原则本身不受影响** —— 覆盖率照旧必须显式声明，只是那个数字要换成重录后算出来的真值。这条原则在等权测试数据下反而更重要：既然覆盖率的输入不可信，就更不能让用户以为看到的是全貌。

## 5. 需求池

### 优先级排序依据（**可操作性 > 覆盖率 > 时效性 > 频率**）

对每个候选问一句：**用户看到这条推送后，能做什么？** 纯基金账户的可执行动作只有 4 个 —— ①申购/加仓 ②赎回/减仓 ③调整定投金额或标的 ④什么都不做。如果一条信号无法影响这 4 个决策中的任何一个，那它的价值就是「哦」，应当降级或砍掉。这就是为什么「穿透重仓股逐票涨跌」即使数据完美也排不进 P1 —— 用户没法交易那些股票。

同时设一条硬约束：**总推送预算 ≤ 4 条/月**。用户已经被骚扰过一次，信任额度很薄。宁可漏报，不可误报。

##### 5.3.1 基准定义与单位陷阱（v2 新增，必须先读）

换基准引入了一个**与 v1 完全相反**的单位要求：

| 场景 | 该用哪个净值 | 原因 |
|---|---|---|
| 相对**滚动高点**回撤（v1 基准） | ✅ `adj_nav` | 分红除权会让 `unit_nav` 跳水，用 `unit_nav` 会把分红误判为暴跌 |
| 相对**成本净值**回撤（**v2 基准**） | ✅ **`unit_nav`** | `cost_nav` 是用户**实际买入价**，与 `unit_nav` 同尺度。`adj_nav` 含历史分红再投资，与成本不同尺度 |

**实测证明这个陷阱有多严重**：

| 基金 | `adj_nav / cost_nav - 1`（错误） | `unit_nav / cost_nav - 1`（正确） | 误差 |
|---|---|---|---|
| 002163.OF | **+161.37%** | **+11.13%** | **+150.2 pct** |
| 其余 7 只 | 与正确值相同 | — | 0（`adj/unit = 1.000`，从未分红） |

002163 有 8 次历史分红（`adj/unit = 2.352`），**若沿用 v1 的「回撤必须用 `adj_nav`」规则，这只基金会显示「浮盈 +161%」** —— 用户明明只赚 11%，却被告知赚了 1.6 倍。这是本 PRD v2 新引入的最高危陷阱，已作为 **§8 B8** 登记。

> 📌 **连带修正**：60 日高点回撤（文案参考口径）的正确算法是「**用 `adj_nav` 定位高点日期，再取该日 `unit_nav` 计价**」。若直接拿 `adj_nav` 当价格算组合市值，会得到 **-42.41%**（正确值 **-29.64%**）—— 本次核算我自己就踩了这个坑，已修正。

##### 5.3.2 状态机配置（推荐）

```
档位阶梯：[-20%, -30%, -40%]      （3 档，暂不设 -50% 档，理由见下）
降级缓冲：当前档位阈值 + 5pct      （-20 档 → 回升至 -15% 以上降档）
同日合并：同一基金同日跨多档 → 合并为 1 条，报最深档
同日多基金：必须合并为 1 条推送   （8 只基金高度相关，不合并会形成轰炸）
冷却期（混合规则）：
    cd_same   = 60 天  ← 同档位 / 更浅档再次进入
    cd_deeper = 7  天  ← 跌破更深档位
```

**为什么是「混合」而不是单一冷却**：同档位重复进入（降级后又跌回来）是**同一条信息重复播报**，必须长冷却；而跌破更深档位是**新信息**，长冷却会把真实的加速下跌吞掉。实测中 008984 于 2026-07-20 跌破 -20% 档、07-30 跌破 -30% 档（间隔 10 天）—— 这是真实的进一步下跌，应当播报，不应被冷却。

**为什么不设 -50% 档**：当前最深的基金是 -26.95%，距 -50% 档有 23pct，该档完全休眠。实测 4 档阶梯会把频率从 0.23 抬到 0.35 次/月（+52%）而当前零收益。**建议保留 3 档，把 -50% 记为扩展点**，待某只基金首次跌破 -40% 后再评估。

##### 5.3.3 边界震荡实测（team-lead 重点提问：会不会在档位边界反复触发 / 反复重新武装）

**结论：会，而且 v1 的设计下相当严重。必须加冷却期 + 同日合并。**

回测方法：取 8 只基金 1249 天（835 个交易日）的 `unit_nav`，按成本净值基准跑状态机，统计**同一只基金相邻两次触发的时间间隔**。

| 配置 | 总触发 | 按日合并 | 次/月 | 间隔<30d | <60d | <90d | 最小间隔 |
|---|---|---|---|---|---|---|---|
| v1 设计（不合并同日多档、无冷却） | 40 | 13 | 0.33 | **20** | 22 | 23 | **0 天** |
| 仅加同日合并 | 24 | 13 | 0.33 | 4 | 6 | 7 | 2 天 |
| 合并 + 缓冲 8pct（**不加冷却**） | 16 | 6 | 0.15 | 2 | 2 | 2 | **6 天** |
| 合并 + 缓冲 15pct（**不加冷却**） | 13 | 4 | 0.10 | 2 | 2 | 2 | **6 天** |
| 合并 + cd_same=60 / cd_deeper=60 | 18 | 9 | 0.23 | **0** | **0** | **0** | **110 天** |
| **✅ 推荐：合并 + cd_same=60 / cd_deeper=7** | **19** | **9** | **0.23** | 1* | 1* | 1* | **10 天** |

\* 唯一的 <30d 间隔是 008984 的 **-20% 档(07-20) → -30% 档(07-30)**，属**更深档位的真实跌破**，不是同一信息重复。按「同档位近距离重复触发」口径统计，**推荐配置下为 0 次**。

**三个关键发现**：

1. **同日跨多档是最大的噪音源**：40 次触发里有 **16 次**是同一天跨两档产生的重复推送（最小间隔 0 天）。仅「同日合并取最深档」这一项改动就砍掉 40%。这是 v1 状态机设计的漏洞 —— v1 只写了「逐级升档」，没规定同一天升两档时该发几条。
2. **加大缓冲无法解决震荡**：缓冲从 5pct 加到 15pct，**最小间隔仍然只有 6 天**（上表第 3、4 行）。因为震荡的主因是单日大幅波动导致的跨档，与缓冲宽度无关。**只有冷却期有效。**
3. **档位线附近拉锯确实剧烈**：实测 NAV 穿越 -30% 线的次数，**005851 达 21 次、013107 达 19 次**（1249 天内）；8 只基金全部出现过**间隔 1 天**的反复穿越。

> ⚠️ 口径说明：上述穿越次数是相对「今天的成本净值」计算的历史穿越，而用户历史上的真实成本并非今天的 `cost_nav`，因此它**不是用户真实的档位历史**，而是「NAV 在固定价格线附近波动有多剧烈」的度量 —— 这正是判断未来震荡风险所需的指标。

##### 5.3.5 成本漂移防护（v2 新增）

成本基准引入了一个 v1 没有的问题：**`cost_nav` 会随用户加仓而变化**，而加仓是用户自己的行为，不是市场信号。

`cost_new = (cost_old + k × unit_nav) / (1 + k)`，其中 `k = 本次加仓金额 / 该基金当前市值`

实测（以 005698 为例，当前 -26.95% / 档位 1）：

| 加仓比例 k | 新成本净值 | 新 vs 成本 | 档位 |
|---|---|---|---|
| 5% | 3.4689 | -26.00% | 1（不变） |
| 10% | 3.4134 | -25.11% | 1（不变） |
| 20% | 3.3706 | -23.51% | 1（不变） |
| 30% | 3.3364 | -22.10% | 1（不变） |
| **50%** | 3.0595 | **-19.74%** | **0（降档！）** |

**防护规则（必须实现）**：

1. **`cost_nav` 发生变化时，重算档位但一律不推送**。因成本变动产生的升档/降档都不得触发推送。
2. 降档重新武装必须来自**净值上涨**（`unit_nav` 上升），而不是成本下降。
3. 用户每月 25 日定投，因此这项防护与 P0-4 存在时序耦合：**24 日发定投提醒 → 25 日扣款 → cost_nav 变化 → 26 日重算档位（静默）**。实现时必须保证 26 日的重算不会误推。

> 注：当前 k 需达到约 50%（一次性投入相当于该基金现有市值一半的资金）才会让 005698 掉出档位，**近期风险低**。但这是一条静默的正确性缺陷 —— 一旦发生，用户会收到一条「回撤收窄」的误导性推送，而这笔收窄是他自己买出来的。防护成本极低，应在本期实现。

## 6. 信号文案规范

### 6.1 强制规则

1. **必须有具体数字 + 具体日期**，禁止只写百分比。反例：`解禁7.6847%`（哪天？多少股？占什么的比例？）
2. **必须标注单位与口径**，见 §6.2 单位对照表。所有百分比必须回答「占什么的百分比」。
3. **第一行必须让用户认出自己的基金**：`{基金简称}({6位代码})，占你总净值 {X.X}%`。禁止只给代码。
4. **必须标注数据时点与滞后**：`（数据截止 YYYY-MM-DD，滞后 N 天）`。
5. **🔒 覆盖率不足时必须显式声明未覆盖部分**，包括是哪几只基金、合计多少比例、为什么覆盖不到。**不得报一个假装完整的数字。**
6. **纯文本，不用 Markdown**（沿用铁律 #20，企微文本消息不渲染 Markdown）。
7. **一条推送最多 8 行正文**；超出则收敛为「Top3 + 其余 N 项见前端」。
8. **🔒 回撤类文案必须区分两个口径并标明哪个是触发口径**：`相对你的成本净值 X%`（**触发口径**）与 `相对近 60 日高点 Y%`（参考口径）。禁止只给其中一个，禁止把两者混着说。
9. **🔒 成本基准的百分比一律用 `unit_nav / cost_nav - 1`**，禁止用 `adj_nav`（见 5.3.1，002163 会因此显示 +161% 而非 +11%）。

### 6.1.1 🔒 硬约束 H1：QDII 穿透缺口的强制表述

**适用范围**：所有穿透类信号 —— P0-1（穿透体检）、P0-4（定投提醒的集中度段）、P1-1（换仓摘要）、P1-2（组合归因）、P1-3（行业异动）。

**强制要求**：文案正文中必须出现以下三要素，缺一不可：

1. **覆盖比例**：`穿透覆盖你总净值的 🧪61.8%`（线上实测 🧪63.0%）
2. **未覆盖比例及其构成**：`未覆盖 🧪38.2%：QDII 2 只合计 🧪24.4%（006555、005698）季报无持仓数据，无法穿透；其余 🧪13.8% 为前十大之外的持股、现金与债券`
3. **对数字的影响**：在给出任何集中度/敞口数字时，必须点明分母 —— 例：`半导体 🧪33.5%（占已穿透的 🧪61.8%，不是占全部净值）`
